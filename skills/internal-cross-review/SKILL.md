# 교차 리뷰

## 리뷰 모드

호출한 스킬의 리뷰 모드를 따른다. `cross-review`는 일반, `adversarial-cross-review`는 공격적 리뷰다. 이 스킬을 직접 호출했으면 사용자가 지정한 모드를 따르고, 지정이 없으면 일반 리뷰를 사용한다.

| 모드 | 검토 기준 |
| --- | --- |
| 일반 | 변경 범위의 정확성, 회귀, 요구사항 누락과 검증 공백을 확인한다. 실제 영향을 설명할 수 있는 문제를 우선한다. |
| 공격적 | 일반 리뷰에 더해 설계 가정, 관련 호출자·피호출자, 신뢰 경계, 실패·복구 경로와 불변식을 검증한다. 경계값, 권한, 데이터 손실, 동시성, 재시도와 호환성 중 관련된 축에서 구체적인 반례를 찾는다. |

공격적 리뷰라고 해서 말투를 거칠게 하거나 지적 개수를 채우지 않는다. 관련 없는 전면 감사로 범위를 넓히지 않는다. 일반 리뷰를 요청받았는데 위험도가 높아 공격적 리뷰가 필요해 보이면 이유를 보고하고, 모드는 임의로 바꾸지 않는다.

## 리뷰어 후보 확인

1. 현재 하네스와 작성에 사용한 모델·공급자를 확인한다. 확인할 수 없는 항목은 미확인으로 남긴다.
2. 하네스 안의 경로를 먼저 본다. 독립 하위 에이전트, 하네스가 제공하는 다른 모델 선택, 설치된 연동 플러그인이 후보다. 연동 플러그인은 등록된 도구 설명이나 스킬을 읽는다. 이름만 보고 명령·옵션을 만들어 내지 않는다.
3. 외부 CLI는 `command -v`(PowerShell은 `Get-Command`)로 설치를 확인한 것만 후보로 둔다. 설치되지 않은 CLI는 호출하지 않고, 설치를 요청하거나 실행하지 않는다.

| CLI | 확인 | 헤드리스 실행 | 모델 |
| --- | --- | --- | --- |
| `codex` | `command -v codex` | `codex exec` | CLI 기본값. GPT·ChatGPT 계열 리뷰는 이 경로로만 실행한다. |
| `grok` | `command -v grok` | `grok -p` | CLI 기본값(Grok 계열). |
| `cursor-agent` | `command -v cursor-agent` | 설치된 버전의 도움말로 확인 | Grok 또는 Composer 계열만. 모델 목록 명령이 있으면 그 출력에서 고른다. |
| `claude` | `command -v claude` | `claude -p` | CLI 기본값. 호스트가 Claude Code가 아닐 때만 후보다. |

- Cursor CLI는 `cursor-agent`로만 감지한다. `agent` 실행 파일은 Grok Build 같은 다른 제품일 수 있으므로 Cursor로 취급하지 않는다.
- 모델 ID를 고정하지 않는다. CLI 기본 모델을 쓰거나, CLI에 모델 목록 명령이 있을 때 그 출력에서 계열만 고른다. 옵션과 입력 방법은 설치된 버전의 도움말로 확인하고, 없는 옵션을 만들어 내지 않는다.

4. 후보마다 실제 공급자·모델, 독립 세션 여부, 입력 방식, 읽기 전용 또는 도구 차단 기능, 기존 인증 사용 가능 여부를 확인한다.
5. 기존 구독이나 API 연결을 사용한다. 인증 정보를 읽어 프롬프트에 넣거나 별도 계정·API 키를 만들지 않는다. 구독 포함 여부나 호출 비용을 모르면 무료라고 단정하지 않는다.

## 리뷰어 선택

- 사용자가 도구, 모델, 공급자 또는 예산을 지정했으면 따른다. 지정이 없으면 작성에 쓴 에이전트·모델 계열과 다른 리뷰어를 우선한다. 같은 계열의 독립 세션은 차선이며, 공급자 교차 리뷰와 구분해 보고한다. 작성 에이전트가 자신의 검토를 독립 리뷰라고 보고하지 않는다.
- Cursor IDE나 `cursor-agent`가 호스트이거나 리뷰어이면 Grok 또는 Composer 계열 모델만 사용한다. Cursor의 모델 목록에 Codex·GPT·Claude 모델이 보여도 추가 과금이 발생하므로 선택하지 않는다. GPT 계열 리뷰가 필요하면 `codex`가 설치된 경우에만 그 경로로 실행한다.
- 다른 공급자를 요청한 경우 실제 모델 공급자를 확인한다. Claude Code, Codex, Cursor, OMP 같은 하네스 이름만으로 공급자를 판단하지 않는다. 다른 공급자임을 확인할 수 없으면 그 제한을 밝힌다.
- 사용 가능한 리뷰어가 하나도 없으면 교차 리뷰를 건너뛰고, 확인한 후보와 없는 이유를 결과에 적는다. 오류로 처리하지 않고, 더 낮은 역량의 모델로 바꾸지 않는다.
- 리뷰 요청을 새 프로그램·플러그인 설치 허가로 해석하지 않는다. 현재 사용 가능한 경로를 먼저 쓴다.

## 검토 범위

1. 사용자 목표와 기준 커밋을 확인한다. 작업 폴더 리뷰는 `git diff HEAD`와 관련 untracked 파일을 포함한다. 브랜치 리뷰는 합의한 기준과 HEAD의 merge-base를 구한 뒤 그 지점부터 비교한다. 커밋된 변경만인지 현재 작업 폴더까지 포함하는지도 구분한다.
2. 리뷰어에게 목표, 선택한 모드, 적용되는 프로젝트 규칙, diff와 필요한 주변 코드를 전달한다. 도구 접근이 없으면 필요한 내용을 프롬프트에 포함한다. 작성자의 결론에 동의하도록 유도하지 않는다.
3. 자격증명이나 관련 없는 개인 파일은 포함하지 않는다. 큰 변경은 논리 단위로 나누고 빠진 범위를 기록한다.
4. 결과 형식은 심각도, 파일과 줄, 근거, 재현 조건, 실제 영향, 수정 제안으로 지정한다. 구체적인 문제가 없으면 그렇게 말하도록 한다. 증거가 부족한 의심은 확정 결함과 분리한다.
5. 공격적 리뷰에는 검증한 가정과 반례, 검토하지 못한 경로도 짧게 요청한다. 시험하지 않은 가정이 남았는데 안전성을 보장했다고 말하지 않는다.

기준 ref와 diff 수집이 성공했는지 먼저 확인한다. 변경이 없거나 수집이 실패하면 리뷰어를 실행하지 않는다. 새 파일 수집을 위해 `git add -N`처럼 인덱스를 바꾸지 않는다.

## 실행 경계

- 리뷰어가 파일을 수정하거나 커밋, 푸시, 외부 메시지 전송을 하지 못하도록 도구 권한을 제한한다.
- 하네스가 읽기 전용 실행을 지원하면 사용한다. 문장으로 쓰기 금지만 요청한 것을 샌드박스로 설명하지 않는다.
- 쓰기를 제한할 수 없으면 모든 실행 도구가 꺼진 호출임을 확인하고 제공한 diff만 검토하게 한다. diff만 전달하는 것으로 도구 권한이 제한되지는 않는다. 도구 차단도 확인할 수 없으면 해당 리뷰어는 사용하지 않는다.
- CLI 옵션과 입력 방법은 설치된 버전의 도움말로 확인한다. 프롬프트는 셸 코드로 보간하지 말고 표준 입력이나 지원되는 파일 인자로 전달한다.
- 종료 가능한 시간 제한을 두고 표준 입력을 닫는다. 시간 초과나 인증 실패 시 원인과 미검토 범위를 보고한다. 권한을 높여 재시도하거나 요청하지 않은 계정으로 우회하지 않는다.
- 비정상 종료, 오류 응답과 빈 출력을 '발견 사항 없음'으로 해석하지 않는다. 종료 코드와 오류를 확인하고 리뷰 미완료로 보고한다.

## 결과 반영

각 지적을 실제 코드와 대조한다. 검토만 요청받았다면 결과를 보고하고 파일은 수정하지 않는다. 구현이나 수정까지 허용된 작업에서는 확인된 문제만 그 범위 안에서 고치고 관련 검증을 실행한다. 사용한 모드, 도구와 확인 가능한 모델·공급자, 검토 범위, 수용하거나 기각한 지적, 남은 한계를 보고한다.
